# Code generation and runtime convention

## Pipeline

```
C source -> Lexer -> Parser -> AST -> CodeGen -> RV32IM assembly (.s)
         -> (GNU as + ld) -> ELF -> simulator / core
```

rvcc emits assembly *text* and relies on the GNU assembler and linker to produce
the ELF. It does not contain an assembler.

## Code generation strategy: naive stack machine (M1)

Evaluating any expression leaves its result in `a0`. Compound expressions are
lowered with a stack machine:

- **Integer literal** -> `li a0, <value>`.
- **Unary** -> evaluate operand into `a0`, then apply: `neg` (`-`), `not` (`~`),
  or `seqz` (`!`, i.e. result is `operand == 0`).
- **Binary** -> evaluate the left operand into `a0` and **push it to the stack**;
  evaluate the right operand into `a0`; move it to `a1`; **pop** the left operand
  back into `a0`; combine with `add`/`sub`/`mul`/`div`/`rem`.

Every intermediate value is spilled to memory (`addi sp,-4; sw a0,0(sp)` /
`lw a0,0(sp); addi sp,sp,4`). There is **no register allocation and no
optimisation** — not even constant folding. This is verbose and slow, and that
is the intended trade-off: simplicity and obvious correctness over code quality.

Signed `div`/`rem` on RV32IM truncate toward zero, which matches C integer
division and gcc; this is checked directly by negative-operand tests in the
corpus.

### Example (`1 + 2 * 3`)

`*` binds tighter than `+`, so `2 * 3` is evaluated first, its result pushed,
then added to `1`. The emitted code contains two push/pop pairs (one per binary
node) — the characteristic shape of the naive stack machine.

## Stack frames and local variables (M2)

Each function gets a stack frame with a fixed **frame pointer `s0`**. Locals are
addressed relative to `s0`, never to `sp` — this is essential because the naive
stack machine moves `sp` while evaluating expressions, so any sp-relative slot
would shift mid-expression.

Frame layout (offsets from `s0`):

```
 -4(s0)   saved ra
 -8(s0)   saved caller s0
-12(s0)   local 0
-16(s0)   local 1
   ...
```

`frameSize = align16(8 + 4 * localCount)`, keeping the stack 16-byte aligned per
the RISC-V ABI. The prologue allocates the frame, saves `ra`/`s0`, and sets
`s0`; the epilogue restores them via `s0` (robust to sp's position) and returns.
Semantic analysis (`sema`) assigns each local its slot and enforces
declare-before-use; code generation only consults the resulting table.

## Control flow, comparisons, and short-circuit logic (M3)

Control flow is lowered with **uniquely numbered labels** (`.Lwhile0`,
`.Lendif3`, ...) generated by a per-compiler counter, so nested and repeated
constructs never collide:

- **if / while / for** use the obvious branch skeletons: evaluate the condition
  into `a0`, `beqz` to the exit/else label, emit the body, `j` back (loops).
  A `for` lowers to init, then a `while` over cond with the post-expression
  emitted at the end of the body. An empty `for` condition omits the test.
- **Comparisons** (`== != < <= > >=`) reuse the binary stack-machine pattern and
  leave a normalised `0`/`1` in `a0` (`slt`, with `xori ...,1` to invert for
  `<=`/`>=`, and `sub` + `seqz`/`snez` for `==`/`!=`).
- **`&&` / `||` short-circuit.** These are *not* ordinary binary nodes: the right
  operand is emitted under a branch so it is skipped when the left already decides
  the result. This is verified behaviourally — tests assign to a variable in the
  right operand and confirm it was never executed.

Nested blocks require no special code generation (statements are emitted in
sequence); scoping is resolved entirely in `sema`, which gives every declaration
its own slot (no reuse) and records each reference's resolved offset on the AST.

## Functions and the RV32 calling convention (M4)

- **Arguments** are evaluated and each spilled to the machine stack, then loaded
  into `a0..a7` immediately before the `call`. Up to 8 arguments are supported.
- **Prologue** saves `ra` and the caller's `s0`, sets the frame pointer, then
  copies incoming argument registers into the parameter slots (parameters are the
  first locals). **Epilogue** restores `ra`/`s0` and returns.
- **Correct-by-construction across calls.** Because the naive stack machine spills
  every intermediate to memory, no value lives in a caller-saved register across a
  call, so a call clobbering `a0-a7`/`t0-t6`/`ra` never corrupts an in-flight
  computation. Recursion and mutual recursion work with no special handling.
- **ABI stack alignment** is met trivially: machine-stack slots are 16 bytes, so
  `sp` is 16-byte aligned at every instruction — including at a call nested inside
  an expression.

## Pointers and arrays (M5)

A minimal type system (`int`, pointer-to-int, array-of-int) is inferred by sema
and annotated onto every expression. Codegen uses it to:

- **decay arrays**: an array-typed variable used as a value yields its base
  address (`addi a0, s0, offset`) rather than a load;
- **scale pointer arithmetic**: `ptr + int` shifts the integer left by 2 (x4)
  before adding; likewise `ptr - int`;
- **address vs value**: `&lvalue` and the address of a store target are produced
  by `genAddr` (a variable's address is `s0 + offset`; the address of `*p` is the
  value of `p`; `*p` loads from that address. `a[i]` is parsed as `*(a + i)`, so
  arrays and pointers share one code path.

All memory is int-width, so every load/store is `lw`/`sw` (no `char`/byte access
in scope) — which is what keeps the type system this small.

## Entry / exit convention (the part both simulators must agree on)

A compiled program is bare-metal. `runtime/crt0.S` sets up the stack, calls
`main`, and hands `main`'s return value (in `a0`) to a target-specific
`__rvcc_exit` routine. Factoring the exit mechanism into a swappable adapter is
what lets the *same* ELF run identically across simulators:

| Target | Adapter | Mechanism |
|---|---|---|
| QEMU `virt` (CI + local harness) | `runtime/targets/exit_sifive.S` | write `(code<<16)\|0x3333` to the SiFive test finisher at `0x100000`; emulator exits with `code`. **Verified.** |
| Spike / riscv-tests-style core | `runtime/targets/exit_htif.S` | write `(code<<1)\|1` to the 64-bit `tohost` symbol (HTIF). Provided for the user's Spike and rv32im-core targets; confirm your core implements HTIF before relying on it. |

The linker script places code/data at `0x80000000` (QEMU `virt` RAM base) and
reserves a small stack ending at `__stack_top`.

## On the instruction-count comparison (`run_tests.py --sizes`)

The harness can report static instruction counts in `main` for rvcc vs
`gcc -O0`. Read it honestly: at `-O0` gcc still **constant-folds**
compile-time-constant expressions, so for M1's constant-only programs gcc's
`main` collapses to a single literal load regardless of expression complexity,
while rvcc evaluates the expression at runtime. The comparison therefore largely
measured rvcc's *absence of constant folding* at that milestone. From M2 on,
variable programs prevent gcc from folding everything, and the comparison shows
the genuine overhead of the memory-spilling stack machine versus gcc's register
ruse (~2.5x on the current corpus) — reported, not hidden.
